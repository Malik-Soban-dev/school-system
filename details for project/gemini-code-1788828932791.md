# Project Rules & Development Guidelines

## 1. Composer & Environment Constraints
*   **The Golden Rule of Composer:** Because the local machine (Windows/PHP 8.3.33) differs from the production container (Linux/PHP 8.4+ target for some packages), ALL local composer commands must use the `--ignore-platform-reqs` flag.
*   **Platform Lock:** Maintain `composer config platform.php 8.4.0` in the local configuration to force composer to resolve packages correctly for the production environment.
*   **Framework Lock:** Do NOT upgrade `laravel/framework` beyond `^11.0` until the Turso ecosystem officially patches compatibility for Laravel 12/13.

## 2. Docker & Stateless Constraints
*   **No Local Storage:** Render's Docker filesystem is ephemeral. It resets on every deploy. You MUST use the `s3` storage driver for user avatars, document uploads, and study materials. The `local` or `public` disk is strictly for temporary cache.
*   **Session & Cache:** Configure `SESSION_DRIVER=database` or `cookie`. Do not use `file`. 
*   **Boot Safety:** Ensure database migrations (`php artisan migrate --force`) are chained to the Docker `CMD` or `ENTRYPOINT`.

## 3. Database & Eloquent Rules
*   **No Raw Queries:** Because libSQL handles some SQL dialects differently than MySQL, always use Eloquent ORM or Laravel's Query Builder.
*   **UUIDs/ULIDs:** Consider using UUIDs or ULIDs for primary keys on public-facing models (like students and invoices) to prevent ID enumeration.

## 4. Git & Version Control
*   **Branching:** Use `main` for Render production. Use `dev` for local testing.
*   **Commit Messages:** Prefix commits with their scope (e.g., `[Auth] added Spatie permissions`, `[Fix] resolved package:discover exit code 255`).
*   **Lock Files:** Both `composer.lock` and `package-lock.json` MUST be committed to ensure deterministic Render builds.
